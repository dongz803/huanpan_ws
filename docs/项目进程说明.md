# 换盘机器人项目进程说明

**更新日期**：2026-09-16
**汇报范围**：仿真执行模块（已有基础）＋ 感知识别模块（本阶段主攻方向）

---

## 一、项目总览

面向硬盘（HDD/SSD）自动换插、服务器兼容性测试与插拔可靠性验证。
机器人平台为 **UR5e + AG95 平行夹具**，目标对象为 **4×3 硬盘架 / 服务器机组**。

项目分两条线并行推进：

| 线路 | 定位 | 当前状态 |
|---|---|---|
| **仿真执行模块** | 运动规划、轨迹执行、力控安全 | 已有基础，本阶段补充力控与抗扰动能力 |
| **感知识别模块** | 识别机架/服务器，为插入提供目标位姿 | 本阶段从零建立，已跑通最小闭环 |

技术栈：**ROS 2 Humble ＋ MoveIt 2 ＋ MuJoCo 3.12 ＋ Ultralytics YOLO（CPU）**

---

## 二、仿真执行模块

### 2.1 已完成能力

- UR5e 六轴机械臂、AG95 夹具完整 14-link 外观与 13-joint 运动链；
- 按实测包络（430 × 85 × 175 mm）建立的 4 列 × 3 行硬盘架，12 个盘位几何完整；
- MoveIt 2 规划（KDL / OMPL / SRDF）＋ MuJoCo 执行桥；
- 应用层 `huanpan_motion` 已按职责分层：

```text
目标位姿 → kinematics → collision_checking → motion_planning
        → trajectory_processing → control → FollowJointTrajectory
```

### 2.2 本阶段新增

**（1）12 个盘位参考坐标系**

原模型只有 `slot_09` 一条插入路线的参考坐标系。本阶段为**全部 12 个盘位**补建了
`slot_00_entry` ~ `slot_11_entry` 与对应的 `slot_NN_goal` 坐标系，
为「识别任意盘位 → 插入任意盘位」打好了基础。

**（2）力控安全模块 `force_guard.py`**

接触力滤波与撤退决策，不依赖 ROS，可独立单元测试：

- 接触力/力矩提取（`body_contact_wrench_world`）；
- 一阶滤波 ＋ 超阈值持续时间判定，**短暂力尖峰不触发，持续超限才触发并锁存**；
- 撤退目标从**接触前的历史轨迹**中选取（`select_retreat_target`），而不是原地后退。

**（3）抗扰动测试模块 `disturbance.py`**

Ornstein-Uhlenbeck 有色关节力矩扰动：可复现（固定随机种子）、有界、
时间相关，用于验证轨迹在扰动下的鲁棒性。

**（4）仿真桥集成**

`bridge_node.py` 已集成上述两个模块，全部参数化开关（默认关闭）：

```
force_guard_enabled / force_guard_threshold_n / force_guard_trip_duration_s ...
disturbance_enabled / disturbance_seed / disturbance_scale ...
```

并发布 `/mujoco/disturbance` 话题，便于外部分析。

## 三、感知识别模块（本阶段主线）

### 3.1 路线决策

经过方案比对，本阶段**放弃仿真相机路线，直接在真实 Intel RealSense D435 上开发**。
理由是真实场景的托盘外观、反光、背景杂乱度与仿真差异过大，仿真数据无法替代真机数据。

**检测目标（已确认）**：**带独立面板的服务器机组**——即机器人要插盘的目标机箱。
不检测周围散落的硬盘托架阵列。单类别，一类名 `server_unit`。

### 3.2 交付物

新建 ROS 2 包 **`src/huanpan_perception`**（23 个 Python 文件、约 3600 行，
其中实现约 2900 行、单元测试约 700 行），
提供 8 个可执行工具，覆盖「采集 → 标注 → 训练 → 评估 → 部署」全流程：

| 工具 | 作用 |
|---|---|
| `capture_node` | D435 实时采集（支持对齐深度、手持交互/定时两种模式） |
| `extract_frames` | 视频抽帧（带近似去重，详见 3.4） |
| `label_dataset` | 标注工具 ＋ 真值预览 ＋ **一致性检查** |
| `train_detector` | 数据切分 ＋ CPU 训练 |
| `evaluate_detector` | mAP ＋ **中心误差（像素/毫米）** |
| `detect_images` | 离线批量推理 ＋ **真值对比总览图** ＋ 预标注 |
| `fake_camera_node` | 用磁盘图片模拟相机流（无相机也能验证 ROS 链路） |
| `detector_node` | ROS 运行时节点，发布检测结果 |

### 3.3 关键技术决策与问题解决

**（1）绕开 `cv_bridge` 与 NumPy 2 的不兼容**

ROS 2 Humble 的 `cv_bridge` 是针对 NumPy 1.x 编译的，与虚拟环境的 NumPy 2.x
一起使用会直接抛 `AttributeError: _ARRAY_API not found`。
本项目手写了 `sensor_msgs/Image` ↔ NumPy 的转换，覆盖
`rgb8 / bgr8 / rgba8 / bgra8 / mono8 / mono16 / 16UC1 / 32FC1` 八种编码，
并正确处理行 padding。

**（2）解决 Torch 虚拟环境与 `ros2 run` 的衔接**

Torch 装在项目虚拟环境，而 `ros2 run` 默认使用系统解释器。
本包入口自带运行时检测：若 Torch 不可导入，自动用虚拟环境解释器重新执行自身，
因此 `ros2 run`、`launch`、直接命令行三种方式行为一致，无需记忆特殊命令。

**（3）视频抽帧的两个隐藏陷阱**

- *近重复*：一段 10 秒视频按 30 fps 有 300 帧，但真正不同的视角可能只有 3~5 个。
- *数据泄漏*（更隐蔽）：若随机切分训练/验证集，验证集里几乎每张都能在训练集
  找到"双胞胎"，**mAP 会虚高而真机失效**。

对策：抽帧按时间间隔采样 ＋ 与上一张已保留帧做近似去重；
训练时**按视频片段分组切分**，保证同一段视频的帧全在同一侧。

**（4）标注质量控制**

标到几十张后，画歪的框肉眼无法发现。新增一致性检查：缺标签 / 空标签 /
框数量异常 / **宽高比离群** / 面积离群 / 框过小 / 框覆盖整图，
并按可疑程度排序输出 + 生成可疑样本拼图。

**（5）人机协同预标注**

先用少量人工标注训出第一版模型，再用它标注剩余图片，人工只做纠正。
工具支持 `--skip-existing` 保护已手工标注的成果，不会被覆盖。

### 3.4 实验与结果

**数据集**

| 项目 | 数值 |
|---|---|
| 真实 D435 图像 | **30 张** |
| 分辨率 | 1280 × 720 |
| 已人工标注 | 9 张 |
| 采集方式 | 手持 D435，视角/距离已拉开（俯拍、平视、斜视） |

**训练实验（CPU）**

| 项目 | 数值 |
|---|---|
| 模型 | YOLOv8n（COCO 预训练微调） |
| 训练轮数 | 235 轮（早停），耗时约 **7.5 分钟** |
| 训练/验证 | 8 张 / 1 张 |
| mAP50 | 0.995 |
| 精确率 / 召回 | 1.00 / 0.98 |

> **必须说明**：该指标建立在 1 张验证图上，属于**过拟合**，只证明
> "数据管线正确、标注对齐、模型学得动"，**不代表真机泛化性能**。

**关键结果**

| 检验项 | 结果 |
|---|---|
| 已标注图上的中心误差 | **2.5 ~ 6.7 像素**（1280 宽，约 0.3%） |
| 已标注图检出率 | 8 / 9（`008` 漏检） |
| **未标注的 21 张上的表现** | 置信度 0.65 ~ 0.96，**稳定命中同一目标** |

最后一项是本阶段最有价值的结论：**9 张人工标注已足以支撑对剩余图片的预标注**，
为后续扩数据节省大量人工。

**推理性能（纯 CPU，无 GPU）**

| 输入尺寸 | 单帧耗时 | 吞吐 |
|---|---|---|
| 640 | 36.3 ms | ~28 FPS |
| 320 | 14.8 ms | ~68 FPS |

D435 彩色流通常 30 FPS，640 尺寸下基本可实时运行。

### 3.5 开发过程中修复的缺陷

工程实现中定位并修复了 6 个实质性缺陷，均补充了回归测试：

| 缺陷 | 后果 |
|---|---|
| 标注工具渲染循环每帧清空当前框 | 用户**完全无法画框** |
| 标签读写使用 `int()` 截断 | 每次加载/保存框漂移 1 像素，反复编辑会累积 |
| 训练输出路径被二次拼接 | 权重落到嵌套目录，且写调用记录时报错 |
| 模型权重下载到工作区根目录 | 污染工程根目录 |
| 虚拟环境重执行判断用 `resolve()` | venv 的 python 是系统解释器软链，判断恒为真，重执行失效 |
| `auto` 分组切分误判 | 文件名各不相同时仍报告"已分组"，给出虚假的指标可信度 |

### 3.6 当前边界

- **仅 2D 检测**，没有手眼标定，尚未输出槽位 6D 位姿；
- 相机装法（固定 eye-to-hand / 腕上 eye-in-hand）**尚未确定**，目前为手持采集；
- 深度通道已支持采集，但**尚未用于定位**；
- 模型仅 9 张训练数据，**不具备实际部署精度**；
- `vision_msgs` 发布分支已完成但**未实跑验证**（依赖包未安装）；
- 系统未安装 `ros-humble-realsense2-camera`，目前采集使用 RealSense Viewer。

## 五、结论

1. **仿真执行模块**已具备规划、执行与力控安全能力，新增 12 盘位参考坐标系
   与力控/抗扰动模块，19 项测试通过。
2. **感知识别模块**从零建立起完整工具链，绕开了 `cv_bridge` 兼容性与环境衔接
   两个工程障碍，并针对视频抽帧的数据泄漏问题做了专门设计。
3. 在 **9 张人工标注**上完成端到端验证：链路正确、标注对齐、模型可用，
   且已验证可对未标注图片进行可靠预标注。
4. 当前瓶颈是**数据量与标定**，而非算法或工程实现。
